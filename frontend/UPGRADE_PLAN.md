# JobIntel 前端改版 + 功能升级方案

> 原则：不复用旧模式包袱，按当前数据能力和用户目标重新设计。
> 当前数据基线：约 1600 条岗位，覆盖深圳/广州/东莞/惠州，角色以 AI Agent 前端、前端工程师为主。

---

## 一、现状诊断

### 1. 前端结构
- React + TypeScript + Vite 单页应用
- 路由：Dashboard、Gap、Roadmap、Clusters、Data、Jobs、Compare、SalaryAudit、RoleDetail、Persona 等 10+ 页
- 状态/数据：React Query + `/api/*` 接口
- 样式：自定义 design-system + Tailwind 风格 token

### 2. 核心问题
- **信息过载**：页面太多，用户进来不知道先看什么
- **价值不直观**：首页缺少“我能拿多少 / 差什么 / 学什么”的直接答案
- **数据口径乱**：同一指标在多个页面重复出现，维护成本高
- **移动端弱**：侧边栏 + 复杂表格，小屏可用性差
- **角色区分弱**：AI Agent 前端 vs 前端工程师的差异不够突出

---

## 二、新架构设计

### 1. 导航重组（3 层 → 1 层）

**旧模式**：侧边栏 10+ 页平铺

**新模式**：单页应用 + 顶部 Tab + 内容区滚动

```
首页（Hero）
├── 能力总览（默认）
├── 岗位市场
├── 学习路线
├── 我的画像
└── 数据后台（管理员）
```

**理由**：用户是求职者/学习者，不是数据分析师。减少跳转，降低认知负担。

### 2. 首页能力总览（Hero）

**目标**：3 秒回答“我现在值多少 / 差什么 / 学什么”

**布局**：
- 顶部：当前目标角色 + 城市下拉选择
- KPI 卡片：样本总量、中位薪资上限、技能缺口数、市场匹配度
- 三档能力分层：必备底座 / 加分稀缺 / AI 工具
- 推荐行动：Top 3 个最高优先级的技能/学习项
- 薪资区间：中位下限–上限 + P25/P75 简表

### 3. 岗位市场页

**目标**：浏览、搜索、筛选岗位

**布局**：
- 顶部筛选：城市、角色、薪资范围、经验
- 左侧：聚合统计（城市分布、角色分布、薪资箱线）
- 右侧：职位卡片列表（虚拟滚动）
- 卡片展开：显示技能标签、薪资、公司、匹配度

**废弃旧字段**：
- `normalized_title` 不再单独展示，只在搜索/去重内部使用
- `search_role` 保留为后台字段，前端不展示
- `first_seen/last_seen` 合并为“更新时间”人性化展示

### 4. 学习路线页

**目标**：从当前技能到目标角色的 Gap → 学习路径

**布局**：
- 当前技能（从 user_profile 读取）
- 缺口技能（从 analytics.personalGap 读取）
- 分阶段路径：基础 → 进阶 → 落地项目
- 每条技能：市场需求 count、学习资源占位

### 5. 我的画像页

**目标**：维护个人技能基线

**布局**：
- 目标角色选择
- 已掌握技能标签（可增删）
- 学习闭环：标记已掌握后，Gap 实时更新
- 保存后全局刷新

---

## 三、废弃旧模式/字段

| 旧模式/字段 | 处理 | 理由 |
|---|---|---|
| 侧边栏 10+ 页 | 改为顶部 Tab + 单页滚动 | 减少跳转，移动端更友好 |
| `normalized_title` 展示 | 前端隐藏，保留后台去重 | 用户不需要看归一化标题 |
| `search_role` 展示 | 前端隐藏，保留后台 | 避免用户困惑 |
| `first_seen/last_seen` | 合并为“更新时间” | 人性化展示 |
| DataPage / DataSchedulePage | 合并为“数据后台” | 非核心功能，折叠 |
| SalaryAuditPage | 合并到岗位市场页 | 薪资解密是后台健康指标，不需要独立页 |
| ClustersPage | 合并到岗位市场页 | 聚类结果可做筛选器 |
| AnalysisShowcasePage | 删除，改为内部组件文档 | 这是开发者页面，不是用户页面 |

## 四、后端接口调整建议

### 保留
- `GET /api/health` — 采集健康度
- `GET /api/analytics` — 分析聚合
- `GET /api/jobs` — 岗位列表
- `GET /api/jobs/:id` — 岗位详情
- `GET /api/scopes` — 作用域选项
- `GET /api/compare` — 角色/城市对比
- `GET /api/role-detail` — 角色细报

### 建议新增
- `GET /api/profile` — 用户画像
- `PUT /api/profile` — 更新画像
- `GET /api/learning-path?role=` — 学习路径推荐

### 建议废弃（前端不再调用）
- 无

## 五、实施步骤

### Phase 1：导航重构 + 首页改版（1–2 天）
1. 删除旧页面路由（DataPage、DataSchedulePage、SalaryAuditPage、ClustersPage、AnalysisShowcasePage）
2. 新建顶部 Tab 导航
3. 重做首页 Hero（KPI + 三档能力 + 推荐行动 + 薪资区间）
4. 保留 Dashboard.tsx 的核心组件，重命名为 HomePage.tsx

### Phase 2：岗位市场页（1 天）
1. 合并 JobsPage + ClustersPage + SalaryAuditPage 的核心功能
2. 新建 MarketPage.tsx
3. 实现筛选 + 卡片列表 + 聚合统计

### Phase 3：学习路线 + 我的画像（1 天）
1. 重做 RoadmapPage.tsx → LearningPage.tsx
2. 重做 PersonaPage.tsx → ProfilePage.tsx
3. 调用新增接口

### Phase 4：数据后台折叠（半天）
1. 保留 DataPage 为 /admin/data 路由
2. 移出主导航，仅管理员可见

### Phase 5：移动端适配（1 天）
1. 响应式断点优化
2. 卡片布局调整
3. 筛选器抽屉化

---

## 六、风险与回滚

- **风险**：改版期间旧页面不可用
- **回滚**：保留旧页面文件为 `.bak`，新路由未稳定前保留双路由
- **数据风险**：无，只改前端展示，不动数据结构

---

## 七、验收标准

- [ ] 首页 3 秒内展示：KPI、三档能力、推荐行动、薪资区间
- [ ] 岗位市场：筛选 + 搜索 + 列表，移动端可用
- [ ] 学习路线：显示当前技能 → 缺口 → 阶段路径
- [ ] 我的画像：可编辑目标角色和已掌握技能，保存后全局刷新
- [ ] 移动端：侧边栏改为底部 Tab 或汉堡菜单
- [ ] 无 console.error，无 404 路由
- [ ] 构建产物 < 500KB（gzip）
